01 · OVERVIEW

What this project does

IQI‑GWO Feature Selection for Image Classification is a lightweight, classical-ML pipeline (no deep learning) that treats feature selection as an optimization problem. Instead of feeding every color-histogram bin into a classifier, it evolves a population of binary “wolves” — each one a candidate on/off mask over the 512 histogram features — toward the subset that maximizes validation accuracy while penalizing feature count.

Handcrafted Features

Every image is reduced to a 512-dim RGB color histogram (8×8×8 bins) — no CNN, no pretrained backbone.

Quantum-Inspired Search

A rotation-gate-style quantum_update() operator occasionally replaces the standard GWO move, adding stochastic exploratory jumps.

Leak-Proof Evaluation

The validation split drives the optimizer's fitness function; the test split is touched only once, at final evaluation.

02 · PROBLEM & OBJECTIVES

Problem statement & objectives

Problem Statement

Raw 512-dimensional color-histogram feature vectors contain redundant and noisy bins that add training cost and can dilute the signal a classifier needs to separate classes. The project's goal, stated directly in the source, is to find a smaller subset of histogram features that classifies at least as accurately — ideally more accurately — than using all 512 bins, without ever letting the optimizer see the held-out test set.

Objectives

  • Improve classification accuracy over a full-feature baseline
  • Reduce feature dimensionality
  • Remove noisy and irrelevant histogram bins
  • Keep the test set strictly out of the search loop to avoid data leakage

06 · THE IQI-GWO ALGORITHM

Improved Quantum-Inspired Grey Wolf Optimizer

Implemented entirely in IQI_GWO.py as a single class. It is a binary, wrapper-based variant of the Grey Wolf Optimizer: each “wolf” is a bit-vector over the 512 histogram features, and the pack hunts for the mask with the highest fitness.

Constructor Parameters

population_sizeNumber of wolves in the pack (default 20, run with 10)
max_itersOptimization generations (default 30, run with 50)
quantum_rateProbability a wolf uses the quantum update instead of GWO move (default 0.3, run with 0.25)
mutation_ratePer-bit flip probability (default 0.1, run with 0.05)
penalty_coefWeight λ on the feature-count penalty (default 0.01, run with 0.001)

Fitness Function

implemented in fitness_function():

Fitness = Accuracy − λ × (Selected Features / Total Features)

Accuracy comes from fitting the surrogate classifier (RandomForest, 50 trees) on the train split restricted to the mask's active columns, then scoring on the validation split. A mask with zero active bits is assigned fitness −1.

What makes it “Improved” and “Quantum-Inspired”

Quantum Rotation Update

Instead of always following the alpha/beta/delta leaders, each wolf has a quantum_rate chance of jumping via quantum_update(): a random rotation angle θ blends each bit with its complement (cos(θ)·bit + sin(θ)·(1−bit)), then re-binarizes at 0.5. This is a stochastic, leader-independent exploration move borrowed from quantum-inspired evolutionary algorithms.

Nonlinear Convergence Coefficient

Classical GWO decays its exploration coefficient linearly (a = 2 − 2t/T). This implementation instead uses a = 2 − 2×(t/T)² — a quadratic decay that stays high (exploratory) longer and then drops off faster, shifting the pack from exploration to exploitation later in the run.

IQI_GWO.py — quantum_update() & mutate()
def quantum_update(self, wolf):
    theta = np.random.uniform(0, 2 * np.pi, self.n_features)
    q = np.cos(theta) * wolf + np.sin(theta) * (1 - wolf)
    return (q > 0.5).astype(int)

def mutate(self, wolf):
    for i in range(self.n_features):
        if np.random.rand() < self.mutation_rate:
            wolf[i] = 1 - wolf[i]
    if wolf.sum() == 0:
        wolf[np.random.randint(0, self.n_features)] = 1
    return wolf
IQI_GWO.py — leader hierarchy & binary position update (inside optimize())
a = 2 - 2 * ((it / self.max_iters) ** 2)   # nonlinear decay

for i in range(self.population_size):
    if np.random.rand() < self.quantum_rate:
        self.population[i] = self.quantum_update(self.population[i])
    else:
        A1, C1 = 2 * a * np.random.rand() - a, 2 * np.random.rand()
        A2, C2 = 2 * a * np.random.rand() - a, 2 * np.random.rand()
        A3, C3 = 2 * a * np.random.rand() - a, 2 * np.random.rand()

        D_alpha = abs(C1 * self.alpha_pos - self.population[i])
        D_beta  = abs(C2 * self.beta_pos  - self.population[i])
        D_delta = abs(C3 * self.delta_pos - self.population[i])

        X1 = self.alpha_pos - A1 * D_alpha
        X2 = self.beta_pos  - A2 * D_beta
        X3 = self.delta_pos - A3 * D_delta

        new = (X1 + X2 + X3) / 3
        self.population[i] = (self.sigmoid(new) > 0.5).astype(int)

    if np.random.rand() < self.mutation_rate:
        self.population[i] = self.mutate(self.population[i])

Each wolf's continuous candidate position (averaged pull from the three leaders) is passed through a sigmoid transfer function and thresholded at 0.5 — the standard technique for adapting continuous GWO to a binary search space. After every iteration, the current best (alpha_pos) is re-scored and logged to self.history (fitness, accuracy, feature count) for later inspection.

07 · FEATURE SELECTION METHODOLOGY

From pixels to a 512-bit search space

Feature Extraction — Load_DataSet.py

Each class lives in its own subfolder; the folder name becomes the label. Every image is:

  1. Read with cv2.imread
  2. Resized to config["image_size"] (128×128)
  3. Converted to a 3D color histogram via cv2.calcHist over channels [0,1,2] with 8 bins each
  4. Normalized with cv2.normalize and flattened → 8×8×8 = 512 features

Why This Design Works for GWO

Because every image collapses to a fixed-length 512-d vector, the optimizer's search space is a constant-size binary string regardless of dataset or image resolution. This keeps IQI-GWO dataset-agnostic: it can select the best histogram bins for a 4-class smoke dataset just as easily as a 30-class plant dataset — only the underlying classifier accuracy signal changes.

Feature selection here is therefore a form of color-channel relevance filtering: bins corresponding to background colors, lighting artifacts, or shared hues across classes are natural candidates to be dropped.

Load_DataSet.py — histogram extraction
img = cv2.imread(img_path)
img = cv2.resize(img, CONFIG["image_size"])
hist = cv2.calcHist([img], [0, 1, 2], None, [8, 8, 8], [0, 256, 0, 256, 0, 256])
hist = cv2.normalize(hist, hist).flatten()
08 · IMAGE CLASSIFICATION PIPELINE

Two classifiers, two jobs

The pipeline deliberately uses two different classifiers for two different purposes — a design choice visible directly in main.py.

1. Baseline — SVC (rbf kernel)

Trained on all 512 StandardScaler-scaled features, evaluated once on the test set. This produces the “before” number in every result comparison.

2a. Search Surrogate — RandomForest (50 trees)

Used inside fitness_function() during optimization — fast to retrain thousands of times across 10 wolves × 50 iterations.

2b. Final Classifier — configurable via Train_Classifier.py

Trained once, after the search finishes, on the selected feature subset (re-scaled). CONFIG["classifier_method"] selects between three options:

RandomForest100 trees, max_depth=20 (default, used in all published runs)
SVCrbf kernel, probability=True
MLPClassifierhidden layers (128, 64), max_iter=500

13 · ADVANTAGES

What the design gets right

  • A true wrapper method — the fitness function directly optimizes held-out validation accuracy, not a proxy statistic like mutual information or variance.
  • The quantum-inspired rotation update gives wolves a leader-independent exploration move, which can help the pack escape local optima that a pure leader-following GWO might converge to prematurely.
  • The nonlinear a decay schedule keeps exploration higher for longer before sharpening into exploitation, compared to the classical linear GWO schedule.
  • Strict train/val/test separation — the optimizer never sees the test set, and the final reported accuracy comes from a single untouched evaluation.
  • A lightweight 512-d histogram representation keeps every fitness evaluation fast enough to run thousands of RandomForest fits across a 50-iteration search, without needing a GPU.
  • Consistent, measured gains across three very different datasets (4, 5, and 30 classes) — the largest gain appears exactly where you'd expect, on the hardest fine-grained 30-class task.
14 · LIMITATIONS

What the source code shows as constraints

  • Feature representation is limited to color histograms — no texture, shape, or learned features. Classes distinguished mainly by color are favored; this likely explains why the 30-class Plant dataset has the lowest baseline (72.45%).
  • fitness_function() wraps the surrogate model's fit/predict in a bare except: that silently sets accuracy to 0 on any failure, with no logging of what went wrong.
  • The use_scaling config key exists but is never read conditionally in main.py — StandardScaler is applied unconditionally regardless of its value.
  • The IQI_GWO class's constructor defaults differ from the values actually used in every published run; importing the class directly without passing CONFIG values yields different (untested) behavior.
  • Runtime scales with population_size × max_iters RandomForest fit/predict calls — the 30-class Plant dataset run took roughly 1 hour 44 minutes for the search alone.
  • No cross-validation: each dataset uses one fixed train/val/test split, so both the search and the final reported numbers carry that split's sampling variance. (README's ± figures imply multiple external runs, but main.py itself performs exactly one.)
  • No automated tests or CI configuration were found in the repository.

16 · CONCLUSION

A small optimizer, a large effect on classical ML pipelines

Across three unrelated, real-world image datasets — smoke detection, histopathology, and fine-grained plant species — IQI-GWO consistently turned an unremarkable full-feature SVM baseline into a strong RandomForest classifier while simultaneously discarding between a quarter and two-thirds of the original 512 color-histogram features. The biggest win appeared exactly where feature selection matters most: the 30-class Plant dataset, where cutting noisy bins lifted accuracy by over 25 percentage points. The implementation stays deliberately simple — no deep learning, one algorithm file, four supporting modules — which makes both the quantum-inspired exploration operator and the classic three-leader GWO hierarchy easy to read end-to-end in IQI_GWO.py.
